## MCP Integration Sprint (Phase 1+2)

The MCP layer was inverted from a generic JSON-RPC passthrough into a dynamic native tool injection pipeline.

### ConnectionPool (`mcp_hub.py`)
- Long-lived stdio subprocesses with **Content-Length framing** (std MCP transport)
- Persistent read loop with buffer parsing — accumulates chunks, splits on `\r\n\r\n`, extracts body by byte count
- Message dispatch via `_pending` futures dict — JSON-RPC `id` routes responses
- Stderr drain task prevents Windows pipe deadlock
- Auto-reconnect: `get()` detects dead connections and reconnects
- Clean shutdown: `terminate()` → 5s timeout → `kill()` — no zombie processes

### MCPAggregator (singleton)
- Loads server config from `workspace/mcp_servers.json`
- `register_server()` / `register_sse_server()` with immediate persistence
- `discover_tools(server)` — connects, calls `tools/list`, caches schemas in memory
- `call_tool(server, tool, args)` — routes through pooled connection
- `inject_native_tools()` — builds and registers dynamic `BaseTool` subclasses into `SkillRegistry`

### MCPNativeTool Factory
- `create_mcp_native_tool(server, schema)` → dynamic `BaseTool` subclass
- Namespaced name: `{slugified_server}_{tool_name}` — no collision with built-ins
- `parameters` mirrors the MCP server's `inputSchema`
- `execute()` closure routes through `MCPAggregator.call_tool()` — MCP is invisible to agents

### SkillRegistry Injection
- `register_dynamic(class)` stores class reference directly (no module/import)
- `get_tool()` detects `"dynamic_class"` key → instantiates directly
- `_inject_mcp_tools()` called during `_discover_tools()` and after `mcp_discover`

### Agent Experience
```python
# Agent sees these as native tools:
github_issues_list(repo="squad-os", state="open")
brave_search_search(query="...")
postgres_query(sql="SELECT * FROM missions")
# MCP transport is completely invisible
```

### Key Architecture Decisions

- **Gate injection at plan parity level**: not in agent prompt — planner writes gates into the JSON task plan, verifier reads from there. This means the LLM never controls which gates run.
- **Workspace fallback chain**: meta-tasks (commit) don't need file verification — if the workspace is gone, the verifier skips gracefully instead of crashing.

## HITL Breakpoint Gate (Afternoon)

### Design

Added a **human-in-the-loop breakpoint** between task scheduling and execution, triggered by the `destructive` flag on tools:

- **`BaseTool.destructive`** — new boolean attribute (default `False`), opt-in per tool
- **Marked as destructive**: `TerminalTool`, `PythonRunnerTool`, `CommitProjectTool`
- **Execution gate**: `execute_task()` checks agent tools before running; if any `destructive=True`, creates a `mission_interrupts` database row and sets task status to `PAUSED_FOR_REVIEW`

### Database

- **`mission_interrupts` table** — stores interrupts per (mission_id, task_idx) with fields: `id`, `mission_id`, `task_idx`, `context`, `error_message`, `user_guidance`, `status` (PENDING|RESOLVED), `created_at`
- **`create_interrupt()`** — inserts and returns the interrupt id
- **`get_task_interrupt()`** — fetches the latest interrupt for a given mission+task
- **`update_interrupt_guidance()`** — stores human's verdict and marks RESOLVED

### Manager (`manager.py`)

- **`execute_task()`** — before agent execution, inspects `agent.tools` for destructive tools. If found, creates an interrupt, sets `task_states[i] = "PAUSED_FOR_REVIEW"`, and returns `True` (non-failure pause — DAG doesn't abort)
- **`execute_dag()`** — wave loop extended to:
  - Also loop while any task is `PAUSED_FOR_REVIEW`
  - Each wave, check resolved interrupts via `get_task_interrupt()`
  - If guidance starts with `APPROVED` → re-queue as `PENDING`
  - Otherwise → mark `FAILED` with human's rejection guidance

### Dashboard (`dashboard.py`)

- **Pipeline tab** — when a task with `PAUSED_FOR_REVIEW` status is selected, shows:
  - Warning banner with interrupt context (which destructive tools)
  - Form with text area for human verdict (default hint: "APPROVED — this looks safe")
  - Submit button calls `update_interrupt_guidance()` → DAG picks it up on next wave
- Imports: added `get_task_interrupt`, `update_interrupt_guidance`
