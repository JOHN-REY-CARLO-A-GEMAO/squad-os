## 2025-05-15 - Command Injection Bypass via Shell Operators and Newlines
**Vulnerability:** The `TerminalTool` validation logic in `_validate_terminal_command` was susceptible to command injection. It naively split commands only by the pipe (`|`) character and only validated the first word of each segment. This allowed attackers to bypass the allow-list by chaining unauthorized commands using other shell operators such as `&&`, `;`, `||`, and `&`. Furthermore, the use of `shlex` without explicit newline handling allowed bypasses using `\n`, as `shlex` would treat newlines as whitespace, causing subsequent commands to be skipped by the validator.
**Learning:** Naive string splitting for security validation of shell commands is insufficient due to the complexity of shell syntax. Even robust tokenizers like `shlex` require careful configuration (e.g., handling newlines) to ensure that all logical command boundaries are correctly identified and validated.
**Prevention:** Always use a proper shell tokenizer (like `shlex`) and ensure all command separators (operators and newlines) are accounted for. Normalize command-separating characters (like newlines to semicolons) before tokenization to ensure the validator consistently identifies and checks every base command in a sequence.
